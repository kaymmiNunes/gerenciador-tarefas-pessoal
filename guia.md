## Apresentação do projeto ao grupo

Grupo, a proposta de vocês é criar um **gerenciador de tarefas pessoal**, ou seja, um sistema simples para ajudar uma pessoa a organizar as tarefas do dia a dia. Esse tipo de projeto é muito útil porque muitas pessoas esquecem compromissos, deixam atividades acumularem ou não conseguem acompanhar o que já fizeram e o que ainda precisam fazer.

O mais importante durante o desenvolvimento é não tentar criar um sistema grande e complicado logo no começo. O melhor caminho é construir um projeto **simples, funcional, organizado e fácil de usar**. Se o sistema permitir cadastrar, visualizar, marcar e organizar tarefas, ele já terá bastante utilidade.

Vocês não precisam criar algo com funções avançadas demais. É melhor entregar um gerenciador simples funcionando bem do que pensar em muitas opções e não conseguir concluir. O foco deve ser produzir algo real, compreensível e apresentável até agosto.

Durante a construção do projeto, o grupo precisa trabalhar com organização, dividir tarefas, registrar decisões, revisar o que foi feito e salvar as versões do projeto no GitHub. Isso ajuda a evitar perda de arquivos, confusões e atrasos.

## 1. Análise simples da proposta do projeto

O projeto de vocês pretende criar um **sistema para organizar tarefas pessoais do dia a dia**. A ideia é que o usuário consiga registrar o que precisa fazer, acompanhar o andamento das tarefas e visualizar o que já foi concluído.

### O que esse projeto pretende resolver
Muitas pessoas esquecem tarefas, não têm uma organização clara da rotina ou acabam anotando compromissos em vários lugares diferentes. O gerenciador de tarefas reúne tudo em um só sistema, facilitando a organização.

### Problema principal
O problema principal é a **dificuldade de organizar e acompanhar tarefas do dia a dia de forma simples e prática**.

### Objetivo geral da aplicação
O objetivo do sistema é **ajudar o usuário a cadastrar, organizar, acompanhar e concluir tarefas pessoais**.

### Utilidade do sistema no dia a dia
Esse sistema pode ajudar a:
- lembrar tarefas importantes;
- organizar a rotina;
- acompanhar o que já foi feito;
- separar tarefas concluídas e pendentes;
- melhorar a produtividade pessoal.

### Público-alvo
O público-alvo pode ser:
- estudantes;
- pessoas que querem organizar melhor a rotina;
- usuários que precisam acompanhar tarefas do dia a dia;
- qualquer pessoa que queira registrar atividades de forma prática.

### Possíveis funções principais do sistema
O sistema pode incluir:
- cadastro de tarefas;
- listagem de tarefas;
- marcação de tarefa como concluída;
- exclusão de tarefa;
- edição de tarefa;
- separação entre tarefas pendentes e concluídas;
- filtro por prioridade ou categoria;
- campo para data ou prazo;
- área com resumo das tarefas.

## 3. Levantamento de requisitos

### O que são requisitos
Requisitos são as necessidades do projeto. Eles mostram o que o sistema precisa fazer e como ele deve se comportar.

### Diferença entre requisitos funcionais e não funcionais
**Requisitos funcionais** são as ações e funções do sistema.  
Exemplo: cadastrar tarefa, listar tarefa, marcar tarefa como concluída.

**Requisitos não funcionais** são características de qualidade do sistema.  
Exemplo: ser fácil de usar, ter aparência organizada, funcionar corretamente no navegador.

### Quais requisitos esse projeto provavelmente terá
Como o projeto é um gerenciador de tarefas pessoal, ele precisa permitir que o usuário registre tarefas, visualize essas tarefas e acompanhe o andamento delas de forma simples.

### Requisitos funcionais
- O sistema deve permitir cadastrar tarefas.
- O sistema deve exibir a lista de tarefas.
- O sistema deve permitir marcar tarefas como concluídas.
- O sistema deve permitir excluir tarefas.
- O sistema pode permitir editar tarefas.
- O sistema pode permitir adicionar prazo ou categoria.
- O sistema deve mostrar quais tarefas estão pendentes.
- O sistema pode mostrar um resumo de tarefas cadastradas e concluídas.

### Requisitos não funcionais
- O sistema deve ter linguagem simples.
- O sistema deve ter aparência organizada.
- O sistema deve funcionar em navegador comum.
- O uso deve ser fácil para o usuário.
- Os arquivos devem estar organizados.
- O sistema deve ser simples de manter.
- O projeto deve ser possível de concluir até agosto.
- O sistema deve responder corretamente aos cliques e comandos do usuário.

### Exemplo de `js/script.js`

```javascript
function adicionarTarefa() {
  const input = document.getElementById("tarefaInput");
  const texto = input.value.trim();

  if (texto === "") {
    alert("Digite uma tarefa antes de adicionar.");
    return;
  }

  const listaPendentes = document.getElementById("listaPendentes");
  const item = document.createElement("li");

  item.innerHTML = `
    ${texto}
    <button onclick="concluirTarefa(this)">Concluir</button>
    <button onclick="excluirTarefa(this)">Excluir</button>
  `;

  listaPendentes.appendChild(item);
  input.value = "";
}

function concluirTarefa(botao) {
  const item = botao.parentElement;
  const listaConcluidas = document.getElementById("listaConcluidas");
  botao.remove();
  listaConcluidas.appendChild(item);
}

function excluirTarefa(botao) {
  const item = botao.parentElement;
  item.remove();
}
```

## 8. Orientação de commit no GitHub

### O que é commit
Commit é um registro de uma mudança feita no projeto. É como salvar uma etapa do trabalho com um nome explicando o que foi feito.

### Por que usar GitHub
O GitHub ajuda a:
- guardar o projeto online;
- evitar perda de arquivos;
- mostrar a evolução do grupo;
- organizar o trabalho.

### Como criar um repositório
1. Entrar no GitHub.
2. Clicar em **New repository**.
3. Escolher um nome, por exemplo: `gerenciador-tarefas-pessoal`.
4. Criar o repositório.
5. Copiar o link do repositório.

### Como organizar os arquivos antes de enviar
Antes de enviar:
- conferir os nomes dos arquivos;
- deixar tudo nas pastas certas;
- remover arquivos repetidos;
- garantir que o sistema abre normalmente.

### Exemplo de comandos básicos

```bash
git init
git add .
git commit -m "Estrutura inicial do projeto"
git branch -M main
git remote add origin LINK_DO_REPOSITORIO
git push -u origin main
```

### Comandos para novas atualizações

